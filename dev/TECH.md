# 技術メモ（TECH）

ROM の解析で分かったこと・改造で使っている場所のメモ。新しく分かったことはここに足して push する（ROM の中身は書かず、番地と意味だけ）。

## メモリ

- メイン/サブ共有RAM: メイン 0x100000 = サブ 0x200000。MB = 0x103f00（サブ 0x203f00）。
- MB の使用（v0.4.17 追加）: 0x3c 開始時のゲージ（0=純正どおり=1周目1面A、1=SPEED UP）・0x3d 開始時のスピード（いまはいつも 0。2026-10-28 にキューブラッシュも 0 に）。どちらもサブがメニュー確定時に書く。※ 0x3a〜0x3e は解除/ロックのコマンド（一時停止中）と重なる。ロックを戻すときは移すこと
- MB の使用: 0x06 MBS_PAUS（0通常 1ポーズ中 2再開 3ゲームオーバー）, 0x0b キューブラッシュ, 0x0c CUBE INFO, 0x0e RANK DISP, 0x1c CUBE LINE V, 0x20 無敵, 0x21 1P START, 0x2b POS DISP, 0x33 CUBE HUNTER, 0x34 CUBE COLOR, **0x3b CUBE LINE H**。0x24–0x2a, 0x2c–0x32 は CmdCalc が使用。
- 空き共有RAM（死亡をまたいで確認済み）: 0x103cf0–0x103dff, 0x1039c6–0x103abf（0x1039c4 = STAGE DISP の設定、0x1039c5 = STAGE DISP 表示中＝メインは 2P のスコアを描かない。#30）。0x103cb0–0x103cef はゲームが死亡/再開時に使う（使うと面が3面に飛ぶバグになった）。
- 使用中: 0x103ed0–ed6（フラグ。ed3 CrEnd, ed4 CUBE COLOR, ed5 V_HAVE, ed6 V_CEW）, 0x103ed8–eff V_LBUF, 0x103ec8–ecf V_LBUF2, 0x103ef0 V_LINV, 0x103dec〜 パレット6の6〜15番（10ワード。サブ Frame が LNPAL から毎フレーム書き、メイン HudPal が 0x800cc へ写す）。CUBE COLOR の写し 0x103cf0（9ブロック×[dest.l, 12ワード]）。
- **サブ私有RAM 0x100e00〜0x101bff はゲームの地形ブロックの読み込み表**（0x20バイト×112個。#1）。改造の変数を置くと地形が欠ける。ゲームは面の開始・再開のたびに 0x100e00〜0x101fff を消す（サブ `$0B9C`）。
- **改造のサブ変数は 0x103400〜0x1039cf**（v0.4.17 で 0x100f00〜0x1014cf から +0x2500 で移した）。元のプログラムは起動時のRAMチェックの後はここに書かない（10面ぶん・キューブ/ボスラッシュで実測。サブ私有RAMで元のプログラムが書かない範囲: 0x100044〜0x100457, 0x100500〜0x1005f7, 0x100826〜0x100dff, 0x102000〜0x1026ff, 0x103310〜0x103fff。スタックは 0x100500/0x100600 から下）。`$0B9C` の後半（`$0BB6`）を ClrHook に飛ばし、同じときに 0x103400〜0x1039cf も消す（以前は消える範囲にあったので同じ動き）。V_LNL=$103732（CUBE LINE の描画済み組み合わせ+1）, V_PSAV=$103800（ポーズ窓の退避 12行×21桁 = 〜$1039f7。#30 で1行増やした）, V_SBUF=$103a00（STAGE DISP の文字列）, メニューの退避 $103600〜。
- スコア表示 `$180a`（`$180e` に入る前の d0 = 描く数−1。表の 2=2P の場所・1=HI・0=1P の場所の順に描く）。改造の ScoreHk は CUBE INFO 中 d0=0（1P だけ）、STAGE DISP 中 d0=1（HI と 1P）。
- 残機 `$50`（自機 0x101000 から）は BCD・最大 99（`$19a2` で 99 で止める）。純正の絵（`$1a72`、段3・桁16〜25 の10文字、字 $3f）は下の桁だけを見て「下の桁 − 1」個描く（10機以上は正しく出ない）。改造の LivHk（表 `$15ce`・`$17fe` の jsr）は STAGE DISP 中は描かず、サブが「字 : 2桁」（= BCD − 1、最大 98）で描く（#30）。
- 面が始まったかの判定（RANK・POS DISP・CUBE の表示）: 自機の絵の番号 `$20101e`/`$20109e`（1P/2P）が 0 でないとき。画面の位置 `$2038de` は4面で 0 のままなので使わない（#4）。
- サブROM: 改造のコード 0x37d78〜、データ DATA_BASE = **0x3a000**〜（#30 で 0x39800→0x39c00、#36 で 0x3a000 に。コードが増えたら上げる）。0x3ffff まで空き。
- 文字の面 TILEA = サブ 0x24c000。セル(段,桁) = (段*64+桁)*2、属性 +1、番号 +$4001。属性 0xdd = パレット6 + 番号上位 0xf。画面 x = 桁*8−96, y = 段*8−16。
- 文字RAM サブ 0x280000（1文字 32B, 4bpp）。0xa00–0xfff は9面で未使用。CUBE LINE は 0xf00〜0xf43（0x29e000〜）、0xf43 は透明の目印（段27・桁51）。
- パレットRAM 0x80000（メインのみ）。パレット6 はゲーム未使用。
- 自機 0x101000: $1 状態(4=死亡中), $1e 絵の番号（通常の面 $80c2/$8102、4面 $b066。スピードアップの処理が $8102 を書く）, $27 死亡演出終了, $69 下位5ビット=スピード段階, $6a ゲージ位置(0=なし 1=SPEED〜7=!), $6c ショット(0=ノーマル 3=ダブル 4=レーザー), $2c 速度（=0x100+0xc0×段階）。
- 入力 MB+0（P1）: bit2 上 bit3 下 bit4 ボタン1（パワーアップ）bit5 ボタン2（ショット）bit6 ボタン3（ミサイル）。キューブ中心 画面 x = objx+5, y = 240−objy。
- サウンド Z80: 0x0000–0xEFFF の合計 0x73B5（0xef00 で補正）。A1 の音量 50%（0x0992/0x0B3B、空き 0xeca0）。

## エミュレータ（MAME）の画面・メモリ（gradius3 ドライバ）

- メイン: K052109 タイル 0x14c000–0x153fff（16bit の下位バイト）, 文字RAM 0x180000–0x19ffff, パレット 0x080000–0x080fff, 共有RAM 0x100000–0x103fff。
- サブ: 共有RAM 0x200000, K052109 0x24c000, 文字RAM 0x280000, K051960 スプライト 0x2c0800–0x2c0fff（下位バイト）。

## 調べて分かったこと

- **パレットの一括ロード `$00F30A`**（純正のコード）：純正スタート・エリアA（位置0）スタート・死亡後の再開では走るが、メニューから面の途中のエリアで始めると走らない。そのため START 表示の間、直前のパレット（メニューで暗くした名残り）が残って色が化ける（#20、alamone さん。dev/research/start-palette.md）。0.4.16 では `$00DAAC`（改造の領域 `$00D8F6..$00DB08`）が START 表示の前後でパレットに約4000回書いている。
  - **v0.4.17 で直した（2026-10-28）**：本当の仕組みは「パレットの出来事の表」（`$4009c` が指す、位置で引く表。処理は `$E318` のタスク＝`$E336` 初期化・`$E356` 毎フレーム、純正はプレイ中＝状態5だけ回す）。面の途中から始めると、開始位置までのパレットの出来事がプレイの最初のフレームでまとめて実行されるので、START 表示（状態2）の間は前の画面のパレットのまま。死んでからの再開は直前のプレイのパレットが残るので化けない。`$F30A` は map 0x0c のパレットアニメの一部で、本題ではなかった。直し方：改造プレイの START 表示の2フレーム目から、元の処理（`$3790`）の後で `$E318` も回す（ShPal）。状態4でゲームが `$400a0` を 0 に戻して初期化し直すので、プレイに入ってからの動きは今までと同じ。パレットの出来事が使う枠 `$43800` の数も変わらない（10通りの開始で確認）。
  - **続き（2026-10-29）：START 表示の間の地形を隠す**。純正は死んで再開するとき（`$3B74`）に `$414E` で地形・背景のパレット $20〜$27・$30〜$37（`$80400〜$804FF`・`$80600〜$806FF`）を 0 にするので、START 表示の間は真っ黒。ShPal の `$E318` がこれを埋め直していた（メニューから面の途中で始めたときも、改造プレイで死んで再開したときも地形が見えた）。ShPal の最後で `$414E` を呼ぶようにした（その人の最初の START で開始位置 `$103f1e` が 0 のときだけは呼ばない＝星が見える今までどおり）。プレイに入ると状態4〜`$E428` でパレットが入り直す。調べ方と結果は `src/lua/research/startblack/`
  - `$00DAAC` のパレットへの書き込みは改造の HudPal（ゲームが使っていないパレット6への毎フレームの書き込み）で、関係なかった。
- **地形を掘る跡のマスク（#6、2026-10-28 判明）**：メイン `$D31A` が掘る処理（3面・6面・10面＝マップ 5・10・13。有効な面は `$D30A` の表を `$1039c0` で引く）。`lea $D4AE,a2` を基点に 32バイト幅のマスク（FF=残す・00=消す。$D640〜$D8FF に丸い穴の形）を文字RAM `$180000〜` に and する。範囲はおよそ **$D4AC〜$DA9F**。**ROM の空き A=$D4AA・B=$D8F6・$D653〜$D8F5（INV_ADDR 等）はこのマスクの一部で、空きではない**。改造がここにコードを置いたため、掘り跡が丸い穴ではなく四角い・点の散った形になり、掘れる速さも落ちる（v0.4.16・v0.4.17 とも。メニューを出さない START でも起きる）。確かめ方：純正にこの範囲だけ改造の中身を書くと改造と同じ跡になる（`src/lua/research/dig/`）。直すには改造のコードを別の空きへ移す
- **面クリア後の突然死（面クリピシャン・#32、2026-10-28 判明）**：純正のバグ。面クリア（`$40029=7`）の7フレーム後、サブ `$72C6`〜 が次の面のために B 面（地形）を作り直す：文字RAM `$288000〜` を消し、全部の升目に通し番号の文字を「番号 `$4001(a1)` → 属性 `$1(a1)`」の順に書く（`$732E`・`$7342`）。番号だけ新しく属性が古い瞬間は、古いバンクの不透明な字になり、メインの地形の判定（`$7BA2` → `$83B0`。升目の属性と文字の4ドットを見る）に当たる。MAME では升目（段14・桁21＝自機の位置 X+$A800〜$AFFF・Y $8800〜$8FFF）の番号がフレームの終わり、属性が次のフレームの頭（約7µs 後）に書かれ、メインの判定（約1.3ms 後）には間に合うので死なない。属性の書き込みを1フレーム遅らせると死ぬ（`src/lua/research/clrdeath/`）。次の面が地図 2・$B（7面・5面）のときはこの処理を飛ばすので、4面・6面のクリアでは起きない。直し方の案：書く順を「属性 → 番号」にする（途中の字は消したばかりの文字RAM＝透明になる。`$732E`〜`$7345` の24バイトを20バイトで書き直せる）
- **面のスクリプト（出来事の並び）**：位置で引く出来事の並びで、カーソルは `$400C0`。位置だけ飛ばすとカーソルが進まず、出来事が出なかったり、まとめて出たりする（#19・#29 の原因の見込み、alamone さん）。
- 調べるときの RAM：`$40029 == 02` は START 表示、`$40007 == 02` はタイトル。メニューが出ている間 `$40029` は 00 のまま。

- **面の出来事の枠のデッドロック**（純正のバグ、alamone さん。2026-10-29 に名前を訂正：以前は「敵の出現スロット」と書いていたが間違い）：`$E336` が面の地図の番号（`$1039C0`。周回は入らない）で表（`$E966`）を選び、カーソル `$4009C` に置く。`$E35E` からスクロール位置と表の位置を比べ（`$E36C`）、`$E3B4` の処理の表へ飛ぶ。処理 1・2 は枠を取って毎フレームの仕事を置く（`$EBF2`・`$EC26`）、3・4 は一度きりの転送（`$EC5E`・`$EFD0`。パレットの出来事 `$E428` もここ）、0 は `$E3B2` の rts（A2 を進めない）。枠が埋まっている・番号 0 のとき、A2 が進まないまま `bra $E36C` で同じ項目を永久に読み直し、垂直同期割り込みはマスクされたまま（`$40030 = 08`）、ウォッチドッグでリセット。敵の出現は別のルーチン（`$DDCA`）。修正（`$E37C`・28バイト）は「A2 が進んだか」で判定するので番号 0 の経路も拾う。止まる場面以外の動きは変えない（6000フレームで `$4009C` の変化が修正前後で同一）。**なぜ4〜5周目で起きるかは未解明**（表は周回で変わらない。周回 1/2/5 で出来事の数が同じ）。「砂漠リセット」との結びつきも未確定。面スキップでの再現（前の面の枠の仕事が残ったまま次の面の表に入る）は有効。
- **ディップスイッチ（alamone さん #31、2026-10-29）**：SW1:1-4 コイン1・SW1:5-8 コイン2（「コイン2なし」は無い。コイン2に投入が無ければ影響なし）・SW2 全部使用・SW3:1-3 使用・**SW3:4 だけが本当の空き**（AAAAA のデバッグ判定以外で読まない）。DSW1 はメイン `$d0001`（負論理。OFF=1）。コイン2のニブル: 1枚1クレ `$F`（初期値）・2枚1クレ `$8`・3枚 `$5`・4枚 `$2`・Invalid `$0`。SW1:5 だけ ON = 1枚2クレ。**`$4266` の AAAAA デバッグ判定は DSW1==`$AA`**（DSW2==`$AA`・DSW3 下位 `$A` も要る）なので、コイン2側に `1010` を作らない。基板に NVRAM/EEPROM は無い（残る設定はディップスイッチだけ）。
- **サブCPUを止めるポーズ**（`$10395E`、alamone さん）：止まったかはサブの RAM では判定できない（サブのフレームカウンタ `$5D0` はゲート `$5D6` より手前で増えるので、止めても毎フレーム変わる）。画面（フレームバッファ）が動くかで見る。止めないと 2・6・7・8 面でポーズ中に画面が動く（120フレーム中27フレーム）。
- **隠し面**：メニューの面の範囲を広げるだけで、グラディウス面・サラマンダ面を選べる（alamone さん）。
- **ステレオ**：サラマンダ面の BGM は元から右だけに振る書き込みが72回（うちチャンネル5が48回）。ほかの面の BGM 5曲とグラディウス面は振り分けなし。基板が YM2151 の L/R を合成しているか片方だけかは実機でしか分からない（MAME はモノで合成）。

- **10面の脱出（#21、2026-10-28）**：ラスボスは進行度 $24D0 で画面が止まって出る。倒すと（ボスの処理 `$1FFA8`）パレット $31 に脱出の要塞の色（`$E926`：$33740 → $80620）を入れ、$24D0〜$2504 はゆっくり、その後は速いスクロール（約2/フレーム）で要塞を抜け、$2FC1 で面クリア → エンディング。脱出の曲 $9A は曲の表（$E242、10面）で進行度 $2540 から。メニューの ❹ は $260000（2026-10-28 に $25C000 から変更。ラスボスの脳の壁が画面から出た所＝要塞のすぐ手前）。スクロールが再開する $24D000 から始めると、ボスを倒したときの地形の書き換え（メイン $203FA・サブ $7900〜）が無いので壊れていない壁が残り、自機が重なる。また、ゲームの敵の出現表の索引は $2600 から先が無く、$260000 以上から始めると表の外を指して止まる → EvPtr が10面で X≥$2500 のときも「X 以上の最初の出来事」を探すようにした。位置で決まらない「ボスを倒したときの色」だけが入らず、要塞が茶色になっていた → StageHook が10面・進行度 $2500 以上の開始/再開で MB_PEND の bit3〜5 を立て、PlayHook がプレイの最初の7フレーム、ゲームの処理（$3A24）の後で `$E926` を呼ぶ（開始位置までのパレットの出来事はプレイの2フレーム目に `$E428` でまとめて入るので、その後で入れ直す）。調べ方は `src/lua/research/escape10/`。
- **NO DEATH（#36、2026-10-29）**：残りフレーム数 = 共有RAM `$103e10`.l（以前サブがボスの表を写していたが誰も読んでいなかった所）。メニュー開始（ApplyStart）で 36000。PlayHook（状態5・ポーズ中は通らない）で、遊んでいる側の自機の状態（`$101001`／2P `$101081`）が 3 のときだけ −1、0 で MB+6=3（ポーズの GAME OVER と同じ）。延長は CmdCnt（START を短く押したとき）で、残り 1800 フレーム以下のときだけ。フリープレイ（`$4004a`≠0）ならそのまま、そうでなければクレジット `$40034`（BCD）が 0 でなければ `$2A76`（純正のクレジット −d7）を呼んで +36000。無敵はサブのメニュー確定（mf_go）で MB+$20=1。ハイスコア・ランキングは CkCR（MODE 1 か 2 なら入れない）。表示はサブ NdDisp（段4・桁27〜33、残り 1800 フレーム以下）。最初の START 表示の案内はサブ NdMsg（MB+$1a の bit2 が下りていて、その人の bit が立っている間。ゲームが START 表示の始めに文字の面を消すので毎フレーム描く）。
- **自機の装備（2026-10-29、#36 の続きで調べた）**：自機 $101000 の $69 下位5ビット＝スピード・bit5〜6＝シールド、$6c＝ダブル/レーザー（タイプA: 0 なし・3 ダブル・4 レーザー）、$6d＝ミサイル、$70〜$7f＝パワーアップの枠（2バイトずつ、下のバイトが `$8ce6` の表の番号。取ると $0800＝使えない）。オプションは $101100 から $50 ずつ4つ（先頭 bit7＝動いている）、シールドは $101f60 から。死んで出直すと $7732 が $68・$6b・$6c を消し、$896c（1P。$89b0 から先は枠の初期化だけ）が枠をタイプの初期値にする。ポーズの装備の変更（EqApply）は、オプション・シールドの枠を 0 にし、$68/$6b/$6c を消して $89b0 を呼び、装備コマンドの Use で付け直す。死ぬ処理は自機の $1a の bit7（当たり）を見る（`$7BA8`）。ポーズの MISS は $1a に $80 を立て、$103ed2（無敵でも死ぬ印。キューブラッシュの区間の終わりと同じ）を立てる。MODE の値: 0 NORMAL・1 NO DEATH・2 CUBE RUSH・3 BOSS RUSH。確かめ方 `src/lua/research/nodeath/`。
- **BOSS RUSH モードで画面が止まる位置（2026-10-29、改造を MAME で無敵・撃ちっぱなしで進めて測った。位置 ÷ 0x100）**：始め→次の面へ進む位置。1面 0AC0→0AC0、2面 0C60→0C60、3面 1CC0（MkIII）→1DC0、5面 0F00（中ボス）→1020、6面 0B60→0B60、7面 07C0→07C0、8面 09C0→09C0、9面 05A0→05B0、10面 011C→止まる所 01E0・02E0・0420・0560・06A0・07E0・1BC8（壁の砲台）・24D0（ラスボス）、面の終わり 2FC0。1・2・6〜8面は始めた所でボスが止まって出る。測り方：`src/lua/research/escape10/poslog.lua` ＋ g3run.lua で POKE `103f08`=面・`103f0b`=2（BOSS RUSH）・`103f20`=1（無敵）、B1 を連打。

## MAME で自動テストするときのコツ（alamone さん）

- コインはタイトルが出てから（`$40007 == 02`）入れる。デモ中に入れると消える。
- メニューを開く START は短く（5フレーム程度）。長いと、開いた直後の同じ押下を「開始」と読んでゲームが始まる。
- メニューの上下左右は 14 フレームくらい押すと効く（6 フレームでは効かない）。
- 書き込みタップ（`install_write_tap`）は終わりの番地を奇数にする。
- スナップショットは `-video none` のままでも撮れる。

## ビルド・テスト

- ビルド: `VERSION=<版> G3BASE=<ROMの置き場> python3 src/mods/build_all.py <出力>`（出力/mame/gradius3 に MAME 用一式）。
  - G3BASE の中身: `rom/genuine/313_main/945_313.f15`・`945_312.e15`、`rw/945_m09.r17`・`945_m08.n17`、`rom/gradius3_313_for_MAME.zip`。純正ROMはユーザーに添付してもらう（リポジトリには無い）。
- MAME は CLAUDE.md の手順でビルド済みを使う。
- アセンブラ（`src/tools/asm68.py`）の制約: オペランドに式は書けない（`TILEA+$298` は不可、数値で書く）。bcc.s が届かないときは .w に。奇数番地のワード読みは不可。
- テスト: `src/lua/run.sh <romdir> src/lua/g3run.lua <outdir>`、環境変数 SEQ / HOLDK / POKE / WATCH / SNAP / OUTLOG / END。
  - キューブラッシュ開始: `SEQ="1400:COIN,1500:START,1620:D,1640:R,1700:START,1820:B1,2120:B1,2420:B1" HOLDK="1495:U:20"`（約2700フレームでプレイ開始）
  - ポーズ: START を約1秒押す（`HOLDK=...,3400:START:70`）。ポーズ内は上下で項目、左右/ショットで値、CONTINUE で B1。
- 調査用の小さなスクリプトは `src/lua/research/`（前の会話の作業フォルダのパスが残っているものは、使う前に直す）。
- リリース: `dev/notes/<版>.json` を作って `python3 tools/release.py <版> <出力> <313メインのフォルダ> <gradius3.zip> dev/notes/<版>.json` → docs/index.html の説明を更新 → commit → **ユーザーに確認してから push**（CLAUDE.md）→ リンクを伝える。前の版の notes の known の項目は次の版にも引き継ぐ。
