キューブラッシュ解析

グラディウスIII（アーケード 313版）9面のキューブラッシュで、キューブの高さがどう決まるかをプログラムと実機相当（MAME）の動きから調べた結果です。改造ROMの CUBE HEIGHT / SHIFT / TYPE と CUBE INFO はこの結果をもとに作っています。

16

4208

高さの決まり方

キューブが出る瞬間に、ゲームは画面の書き換えごとに1ずつ増えるタイマー（16ビット）を見て、その値から高さを決めています。

  • 高さの番号 ＝（タイマーの下位8ビット xor 上位8ビット）の下から3〜6ビット目。0〜15 の16通りです。
  • 番号ごとの高さは表で決まっていて、真ん中あたりの4組（5と6、7と8、9と10、11と12）は同じ高さです。そのため実際の高さは12種類です。
  • 高さ以外は、出たあとに決まります。飛んでくる方向はそのときの自機の位置、速さはランクで決まります。

H は改造ROMの表示に合わせて 1〜16 で数えています（1 が一番下、16 が一番上）。

出るタイミング

  • 2個目以降が出るタイミングは、1個目からのフレーム数で決まっていて毎回同じです。
  • 間隔はすべて16フレームの倍数です（16〜80フレーム）。99個目は1個目の4208フレーム後に出ます。
  • この間隔はゲームの処理が進んだフレームで数えます。タイマーのほうは画面の書き換えごとに増えます（下の「ずれ」の話につながります）。

並びが決まる仕組み

出る間隔が固定なので、1個目が出た瞬間のタイマーの値だけで99個すべての高さが決まります（処理落ちがない場合）。違う並びになるのは全部で 2880 通りです。

H・S・T の意味と選び方

改造ROMのメニューの CUBE HEIGHT（H）・SHIFT（S）・TYPE（T）は、この 2880 通りに付けた番号です（16×4×45＝2880）。

  • 見て意味が分かるのは H だけです。H は1個目の高さです。
  • S と T は、ゲームの中に元からある値ではありません。並びを呼び分けるために付けた「カタログ番号」です。値を見て「どんな並びになるか」を考えて決めるものではありません。
  • ですから、先に並びを見て、気に入った並びの H・S・T をメモしてメニューで選ぶのが使い方です。並びは下の「並びを見る」で H・S・T を選ぶと、99個ぶんがグラフと数字で出ます。
値何を表すか1つ変えるとどうなるか
H1〜161個目の高さ（上の表の番号。1 が一番下）1個目の高さが変わり、2個目以降もほとんど別の並びになります
SA〜D並びの系統（4つ）1個目は同じままで、2個目以降の約半分〜4分の3が別の高さになります
T01〜45同じ H・S の中の通し番号近い番号どうしは似た並びです（99個のうち違うのは4〜26個、多くは8個ほど）。ただし途中に3か所、ほとんど別の並びに変わる境目があります

選び方の例

  • 同じ並びをくり返し練習する：H・S・T を決めたら変えずに使う。メニューで待つ時間を変えても同じ並びになります。
  • 少しだけ違う並びで慣らす：T を1つずつ動かす（似た並びが続きます）。
  • まったく違う並びにする：H か S を変える。
  • どれでもよい：H・S・T を適当に選んでも、2880 通りのどれかになるだけです。困ることはありません。
  • 処理落ちがあると、その分だけ並びがずれます（下の「処理落ちによるずれ」）。ずれて並びが変わったかどうかは CUBE INFO で分かります。
細かいしくみ（番号の付け方）
  • タイマーの値は65536通りありますが、高さの計算に下2ビットは使われないので、実際に違う並びになるのは 2880 通りです。
  • H：1個目の高さの番号。
  • S：1個目の瞬間のタイマーの下から3〜4ビット目。出る間隔が16の倍数なので、99個すべてでこの2ビットは変わりません。
  • T：同じ H・S の中の残りの違い。45通りあり、タイマーの値が小さい順に番号を付けています。タイマーの上の方の桁が繰り上がるところが、T の「境目」になります。
  • 同じ高さの番号を1つにまとめて数えても 2880 通りはすべて違う並びです。
  • MAME で H5・S B・T12 を選んで通しで記録し、99個すべての高さが計算どおりになることを確かめています。

処理落ちによるずれ（LAG）

  • 処理落ちしたフレームでもタイマーは増えますが、出る間隔のほうは進みません。そのため処理落ちが1フレームあるごとに、タイマーが計算より1つ先に進みます。
  • ずれは戻らず、そのラッシュの間ずっと足されていきます。上限はありません。
  • 高さの計算に下2ビットは使われないので、1個目の瞬間の下2ビット次第で、1〜3フレームのずれなら並びが変わらないことがあります。4フレーム以上ずれると、そこから先の高さはほぼ別物になります。
  • 改造ROMの CUBE INFO では、並びが実際に変わったときだけ「LAG:12+0005」（最初に並びが変わったキューブの番号＋ずれの累計フレーム数）を出します。
  • 無敵でキューブを大量に積もらせたまま99個通した試験では、処理落ちは0フレームでした。オプションやレーザーで撃ち続けたときにどこまでずれるかは、まだ測っていません。

くっつく判定

  • キューブが壁やほかのキューブに当たったとき、画面の左端・上下の端に来たときに「くっついた」ことになり、背景の一部に変わります。この判定はサブCPU側で行われています。
  • 画面の外へ抜けたキューブはくっつきません。試験では99個中97個がくっつきました。
  • 改造ROMのキューブラッシュでは、1個くっつくたびに 1000点が入ります。ハイスコア・ランキング・残機の増加には影響しません。

どこで反応するか（キューブの番号で決まる）

キューブは右端（x=350あたり）に出て、決まった時間だけ左へまっすぐ流れ（1フレーム2ドット）、その時間が終わった瞬間にそのときの自機の位置へ向きを1回だけ決めてまっすぐ飛んできます。追いかけ直しはしません。

  • 待ち時間は「何個目か」を2で割った値で16通りの表から決まります。2個ずつ同じ動きになり、32個で一周します（1個目だけは単独）。高さの並び（H・S・T）とは関係ありません。
  • 反応する位置は「350 −（待ち時間×2）」ドット。待ち時間が176フレーム以上のキューブは、反応する前に左端に着いてそのままくっつきます（反応しない）。
  • 飛んでくる速さはランクで決まります（ランク0〜5は1フレーム4ドット、以後2ずつ上がるごとに0.5ドット速くなり、14〜15で6.5ドット、16以上は7ドット）。
  • 「手前で反応する／後ろから来る」は自機の位置しだいです。下の表は自機が初期位置（x=111）のままの場合です。

シミュレーター

自機の位置とランクを決めて、99個のキューブがどう流れてどこで反応するかを動かして見られます。再生中はキーボードの矢印キー、ゲームパッドの十字キー（スティック）、または図の下のパッド（または図の中）をなぞると自機を動かせます（なぞった分だけ自機が動くので、自機を指で隠さずに操作できます）（キューブはゲームと同じく、反応した瞬間の自機の位置へ向かいます）。止めているときは図の中をクリック（タップ）すると自機がそこへ移ります。キューブ同士・地形にくっつく動きは省いています（画面の左・上下の端でくっつき、右へ抜けたものは消えます）。
